🔬 実験・ラボデータ管理システム (Experiment & Lab Data Management System)
このリポジトリは、科学実験やラボのデータを効率的に管理するための軽量なWebアプリケーションです。実験のテンプレート定義、個々の実験インスタンスのデータ入力、プレートレイアウトの管理、および実験プロセスの可視化（スキーム）をサポートします。

✨ 特徴
実験フォーマットの定義:
様々なタイプの実験に対応するため、カスタムフィールド（テキスト、数値、日付、ドロップダウン、チェックボックス、ファイル添付）を持つ再利用可能な実験フォーマットを定義できます。
フォーマットに属するフィールドのデフォルト値や共通の設定を保存する「パターン」を作成し、新しい実験のデータ入力を効率化できます。
実験インスタンスの管理:
定義済みのフォーマットに基づいて、個々の実験インスタンスを作成し、データを記録できます。
実験データの変更履歴が詳細に記録され、監査可能です。
アップロードされたファイルはアプリケーションによって管理されます。
プレートレイアウトの管理:
96ウェル、384ウェルなどの標準プレートに加え、カスタムチューブ形式のレイアウトを定義・管理できます。
各ウェル/チューブに対してカスタムプロパティ（例：サンプルID、濃度）を定義し、データを入力できます。
定義したプレートレイアウトは、既存の実験インスタンスにリンクさせ、ウェルごとのデータを入力・管理できます。
実験スキーム（ワークフロー）の視覚化:
実験プロセスやワークフローをノードとエッジで表現する「スキーム」を作成できます。
スキーム内のノードを、特定の実験インスタンスや実験フォーマットにリンクさせることができ、関連性を視覚的に把握できます。
データのエクスポート:
実験インスタンスのデータをExcel (.xlsx) およびPDF形式でエクスポートできます。これには、実験の詳細、フィールド値、およびリンクされたプレートのウェルデータが含まれます。
簡易的なユーザー追跡:
実験やレイアウトの作成者、変更履歴などの情報は「ユーザー名」として記録されます。本格的なユーザー認証システムは含まれていませんが、誰がいつ何を行ったかの簡易的な追跡が可能です。
🚀 テクノロジー
バックエンド: Flask, Flask-SQLAlchemy
データベース: SQLite (デフォルト設定、他のRDBMSへの変更も可能)
フォーム: Flask-WTF, WTForms-SQLAlchemy
データエクスポート: openpyxl (Excel), xhtml2pdf (PDF)
JavaScriptライブラリ: LeaderLine (スキーム視覚化), Interact.js (スキームのドラッグ操作)
フロントエンド: Jinja2 (テンプレート), Bootstrap 4 (CSSフレームワーク)
🎯 前提条件
Python 3.8 以降
pip (Pythonパッケージインストーラ)
📦 インストールと起動
リポジトリをクローンする:

git clone https://github.com/your-username/your-repo-name.git # ご自身のレポジトリURLに変更してください
cd your-repo-name
仮想環境を作成・アクティベートする:
依存関係の衝突を避けるため、仮想環境の使用を強く推奨します。

python -m venv venv
# Windowsの場合
.\venv\Scripts\activate
# macOS/Linuxの場合
source venv/bin/activate
必要なパッケージをインストールする:

pip install -r requirements.txt
注意: xhtml2pdf のPDFエクスポート機能は、システムにインストールされているフォントに依存する場合があります。特に日本語フォントをPDFに含めたい場合は、IPAexGothic などのフォントがシステムにインストールされていることを確認してください。

アプリケーションを起動する:

python run.py
アプリケーションは通常、http://127.0.0.1:5000/ で利用可能になります。

💡 使い方
アプリケーションを起動したら、ブラウザで http://127.0.0.1:5000/ にアクセスします。

1. 実験フォーマットの作成 (/formats)
新しい実験を開始する前に、その実験で記録したいデータ項目（フィールド）を定義した「実験フォーマット」を作成します。

ナビゲーションバーの「Formats」をクリックし、「Create New Format」から新しいフォーマットを作成します。
フォーマット名と説明を入力し、「Save Format」をクリックします。
作成後、フォーマットの編集画面に遷移します。ここで、「Add New Field」セクションから、そのフォーマットに紐づくフィールドを定義します。
Field Name: データの項目名（例: "Sample ID", "Temperature"）
Field Type: データの種類（Text, Number, Date, Dropdown, Checkbox, File）
Units: 数値型の場合の単位（例: "°C", "mg/mL"）
Required: 必須項目かどうか
Dropdown Options: ドロップダウン型の場合の選択肢（コンマ区切り）
フィールドを追加したら、既存のフィールドリストに表示されます。
パターン (Patterns): 「Create Pattern」ボタンをクリックすると、そのフォーマット専用のパターンを作成できます。パターンはJSON形式でフィールドのデフォルト値を定義し、新しい実験インスタンスを作成する際に自動で値を埋めることができます。
2. 実験インスタンスの作成とデータ入力 (/experiments)
フォーマットが準備できたら、実際の実験データを記録する「実験インスタンス」を作成します。

ナビゲーションバーの「Experiments」をクリックし、「Create New Experiment」から新しい実験インスタンスを作成します。
Experiment Title: 実験のタイトル
Experiment Date: 実験を行った日付
Experiment Format: 前の手順で作成した実験フォーマットを選択します。
Username: この実験を記録しているユーザー名（自由に設定できます）
Status: 実験の現在のステータス（Draft, In Progress, Completedなど）
「Proceed to Data Entry / Save Experiment」をクリックすると、インスタンスが作成され、データ入力画面に遷移します。
データ入力: 各フィールドに対応するフォーム要素が表示されます。「Apply Pattern (Optional)」ドロップダウンから既存のパターンを選択し、「Load Pattern Data」ボタンをクリックすると、パターンで定義された値がフォームに自動入力されます。
データ入力後、「Save Data Fields」をクリックして保存します。
「Update Details」で実験の基本情報（タイトル、日付、ステータス）を更新できます。
3. プレートレイアウトの管理 (/layouts)
プレートデータ（ウェルごとの情報）を管理するための「プレートレイアウト」を定義します。

ナビゲーションバーの「Layouts」をクリックし、「Create New Layout Template」から新しいプレートレイアウトを作成します。
Layout Name: レイアウトの名称
Layout Type: プレートのタイプ（96-well Plate, 384-well Plate, Custom N Tubes/Wells）。選択に応じて「Rows/Columns」または「Number of Tubes/Wells」が入力可能になります。
Creator Username: このレイアウトを作成したユーザー名。
「Save Layout」をクリックします。
作成後、レイアウトの編集画面に遷移します。ここで、「Add New Well Property」セクションから、各ウェル/チューブに記録したいカスタムプロパティを定義します。
Property Name: プロパティ名（例: "Sample ID", "Concentration"）
Property Type: データ型（Text, Number, Boolean）
4. 実験インスタンスにプレートをリンクしてウェルデータを入力 (/experiments/<instance_id>/layouts/add)
作成したプレートレイアウトを特定の実験インスタンスに紐づけ、ウェルデータを入力します。

既存の実験インスタンスの「View」ページ (例: /experiments/<instance_id>) に移動します。
「Linked Plate Layouts & Well Data」セクションの「Link New Layout」ボタンをクリックします。
Select Plate Layout: リンクしたいプレートレイアウトを選択します。
Name for this plate in experiment: この実験内でのプレートの名称（例: "Input Plate 1", "Reagent Tubes A"）。この名称は、一つの実験内でユニークである必要があります。
「Link Layout to Experiment」をクリックします。
リンクが成功すると、ウェルデータ入力画面に遷移します。定義されたウェルプロパティに基づいて、各ウェル/チューブのデータ入力フォームが表示されます。
データを入力後、「Save All Well Data」をクリックして保存します。
5. 実験スキーム（ワークフロー）の管理 (/schemes)
実験のプロセスやワークフローを視覚的に表現するスキームを作成・設計します。

ナビゲーションバーの「Schemes」をクリックし、「Create New Scheme」から新しいスキームを作成します。
Scheme Name: スキームのタイトル
Creator Username: スキームを作成したユーザー名。
「Save Scheme」をクリックすると、スキームの設計画面に遷移します。
スキーム設計:
「Add Node」ボタンをクリックしてノード（ステップ）を追加します。ノードにはラベル、説明、色を設定できます。
ノードを既存の実験インスタンスや実験フォーマットにリンクさせることもできます。
ノードはドラッグ＆ドロップで配置できます。
ノードをクリックすると、そのノードの編集モーダルが開きます。
エッジ（接続）の作成: edit_scheme.html のJavaScriptコメントによると、ノードをクリックすると、最初のクリックがソースノード、2回目のクリックがターゲットノードとなり、エッジが作成されます。
ノードまたはエッジを選択し、Delete キーを押すことで削除できます（ただし、これは将来的な機能であり、現在の実装ではJavaScriptコードの一部として示唆されています。バックエンドのAPIは存在します）。
6. データのエクスポート
実験インスタンスの「View」ページ (例: /experiments/<instance_id>) に移動します。
ページ上部の「Export」ドロップダウンメニューから、次の形式でデータをエクスポートできます。
To Excel (.xlsx): 実験の詳細、フィールド値、およびリンクされたすべてのプレートのウェルデータを含むExcelファイルがダウンロードされます。
To PDF: 実験の詳細、フィールド値、およびリンクされたすべてのプレートのウェルデータを含むPDFファイルがダウンロードされます。
⚙️ 設定
主要な設定は app/__init__.py で行われます。

app.config['SECRET_KEY']: Flaskアプリケーションのセキュリティに不可欠な秘密鍵です。本番環境で使用する場合は、必ずこの値を強力なものに変更してください。
app.config['SECRET_KEY'] = 'your_very_strong_and_secret_key_here'
app.config['SQLALCHEMY_DATABASE_URI']: データベース接続URIです。デフォルトではプロジェクトルートに site.db というSQLiteファイルが作成されます。
PostgreSQLを使用する例: postgresql://user:password@host:port/dbname
MySQLを使用する例: mysql+pymysql://user:password@host:port/dbname
app.config['UPLOAD_FOLDER']: ファイル添付機能で使用されるアップロードフォルダのパスです。デフォルトでは app/static/uploads になります。
⚠️ 注意事項
ユーザー認証機能: 本アプリケーションには、本格的なユーザー認証、ロールベースのアクセス制御（RBAC）機能は含まれていません。username フィールドはデータの記録者を示すためのものであり、アクセス制限を行うものではありません。
データ削除: 実験インスタンス、フォーマット、レイアウトを削除すると、関連するすべてのデータ（フィールド値、ウェルデータ、変更履歴など）もデータベースから削除されます。ファイルシステム上のアップロードファイルも削除されます。この操作は元に戻せません。
秘密鍵の管理: SECRET_KEY はアプリケーションのセキュリティに非常に重要です。公開リポジトリにコミットする場合、この値を直接書くのではなく、環境変数などを使って管理することを検討してください。
